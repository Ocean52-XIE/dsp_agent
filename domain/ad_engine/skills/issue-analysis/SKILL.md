# Issue Analysis

## 什么时候使用

当内置路由规则判断问题属于问题分析时，使用本 skill。

典型场景：
- 成本超标
- 胜率下降
- 召回骤降
- 精排抖动
- 冷启动无量
- 排查错误、异常、故障

## 执行规则

1. 先明确问题现象，再分析原因
2. 需要证据时必须调用 `domain_retrieve`
3. 分析时区分：
   - 证据支持的结论
   - 合理假设
   - 建议继续排查的方向
4. 如果证据不足，不输出伪确定性结论
5. 给出可执行的排查步骤和修复建议

## 推荐输出结构

```text
问题判断

可能原因

建议排查步骤

修复建议

证据来源
```

## 检索建议

- 默认使用 `hybrid`
- 如果用户显式提到函数、文件、模块实现，可以转向 `code_first`
- 如果更像经验排障或案例总结，可以偏向 `wiki_first`
