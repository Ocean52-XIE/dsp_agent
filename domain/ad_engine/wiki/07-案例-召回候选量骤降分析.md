# 案例：召回候选量骤降分析

> **模块**: ad-recall
> **标签**: 排障案例、召回、候选量
> **关键词**: 召回、候选量、骤降、索引、过滤、recall、candidate

## 问题现象

召回阶段的候选广告数量出现明显下降：
- 候选集从 1000+ 降到 100 以下
- 后续精排阶段输入不足
- 整体广告填充率下降

## 排查步骤

### 1. 确认索引状态

```bash
# 检查索引文件是否存在
ls -la /path/to/index/

# 检查索引构建时间
stat /path/to/index/*.idx
```

常见问题：
- 索引构建失败
- 索引版本回滚
- 索引文件损坏

### 2. 检查过滤条件

检查 `recall_service.py` 中的过滤逻辑：
- 定向条件是否过严
- 频控参数是否合理
- 黑名单是否过大

```python
# 检查过滤条件
def select_recall_candidates(query, filters):
    # 打印各阶段过滤数量
    print(f"索引召回: {len(raw_candidates)}")
    print(f"定向过滤后: {len(after_targeting)}")
    print(f"频控过滤后: {len(after_freq)}")
```

### 3. 排查下游依赖

检查召回依赖的下游服务：
- 人群包服务是否正常
- 特征服务是否返回完整
- 索引服务是否响应正常

### 4. 检查流量特征

分析请求特征变化：
- 流量来源是否有变更
- 用户群体是否有变化
- 请求参数是否正常

## 常见原因

| 原因 | 症状 | 解决方案 |
|------|------|---------|
| 索引延迟 | 索引时间戳过旧 | 重建索引 |
| 过滤条件过严 | 各阶段数量差异大 | 调整过滤阈值 |
| 特征缺失 | 依赖特征为空 | 修复特征服务 |
| 人群包过期 | 定向命中为0 | 更新人群包 |

## 解决方案

### 方案一：重建索引

```bash
# 触发索引重建
curl -X POST http://index-service/rebuild

# 验证索引状态
curl http://index-service/status
```

### 方案二：放宽过滤条件

```python
# recall_service.py
# 临时放宽频控限制
freq_cap = {
    "max_impressions": 5,  # 原值 3
    "time_window": 3600,
}
```

### 方案三：添加降级策略

```python
# 当候选量不足时启用兜底策略
if len(candidates) < MIN_CANDIDATES:
    candidates = get_fallback_candidates(query)
```
